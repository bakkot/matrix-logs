Another hopefully useful thing (at least for me if no one else), is that searchfox's wubspecs repo can now sorta sync the list of outstanding spec PRs and then sorta ingest those to try and help make it easier to understand what's going on with PRs or different PRs. So the workflow is sorta, someone goes to https://searchfox.org/wubspecs/spec-prs and hits the sync button there which then pulls down the PR metadata cheat-sheet that https://github.com/mozsearch/spec-pr-state crated via an hourly github action, which then lets the sync stuff just do a bunch of git operations. Then I click on one of the specs there and end up on a spec PR listing page like https://searchfox.org/wubspecs/spec-prs/fetch for fetch and then if all the PRs aren't already imported and there are less than 50 of them, there is an "import" button and clicking it should import them all which then tries to ~semantically index them, which includes running the above-mentioned bikeshed parser for its semantics and magic. If I then click on one of the "with pull requests" links, I can end up (with anchor for example) at https://searchfox.org/wubspecs/rendered-prs/fetch/fetch.bs#destination-type which by default tries to show all of the effects of all of the imported PRs in a second column next to the current trunk spec with rendered blame (hover on the stuff on the left to see blame). There's actually a faceting UI at the top of the page which probably should move into the fancy bar on the right like it is elsewhere in searchfox. But so you could turn off already approved PRs or stuff. Screenshot above.
